# แปลงเลขเอกสารเก่าที่ DB (ครั้งเดียว)

ตัดสินใจ 14 พ.ย.: เลขเอกสารทั้งระบบเป็น **PREFIX 3 ตัว + YYYYMMDD + ลำดับ 4 หลัก** (เช่น `IOR202611140003`) · เอกสารเก่าแปลงที่ DB ครั้งเดียวตอนอัปเดต ไม่ให้หน้าเว็บแปลงเอง (ปิด sweep ด้วย hotfix `DOCID-SWEEP-OFF`)

ตัวแปลง: `whrm-backend/scripts/migrate-docids.mjs` · ตาราง: migration `012_docid_migration.sql`

## แปลงอะไร

| ที่ | แปลง |
|---|---|
| `kv_store` (`whrm_*`, `WMS-*`) | ค่า + คีย์ที่เป็นเลขเก่า (ไม่แตะช่อง Lot / Batch) · version +1 → หน้าเว็บรับค่าใหม่ |
| `doc_store` | เลขใบ (`TRF-<ms>` → `TRF…`) + เนื้อใน |
| `weighing_report` / `weighing_item` | เลขใบชั่ง `ROO20261002-0012` → `ROO202610020012` · Trip No |
| `sbo_order` / `sbo_handoff` / `quotation` | เลขเก่าที่อยู่ในข้อมูล (เลข SBO / QT เดิมไม่เปลี่ยน) |
| `ru_cancel.rma_no` | `RMA-…` → `RMA…` |

ไม่แตะประวัติ (`audit_log` · `kv_history` · `doc_history` · `bus_message`) · แผนที่เลขเก่า → ใหม่เก็บใน `docid_map`

กติกา = DOC ID STANDARD v1.2.0 ของลูกค้า ยกเว้น `SO-YYYYMMDD-NNN` → **SOA** (ไม่ใช่ SBO)
- เลขที่คำนวณได้ตรง (IO / RA / EO / RMA / RO / TXN / FGT / PL-REQ / เลขใบชั่ง) → ตัด "-" เติม 0
- เลขที่ต้องออกใหม่ (`TRF-<ms>` · `FGA-<ms>` · `PQ` / `WMS` · `TRFddmmyyyy-N` · `IO-SO-<n>`) → เรียงตามเวลาจริง ต่อจากตัวนับกลาง + ตัวนับหน้าเว็บ + เลขมาตรฐานที่มีอยู่แล้ว (ไม่ชนกับเลขที่ออกไปแล้ว)
- แผนที่เดิมของหน้าเว็บ (`whrm_idmap_v1`) ใช้ต่อ → เลขที่หน้าเว็บเคยแปลงไว้ ได้ผลเดิม

## ขั้นตอนวันแปลงจริง (นัดลูกค้า)

1. **แจ้งทุกเครื่องให้ส่งข้อมูลให้หมด แล้วปิดหน้าเว็บ** — ป้ายมุมขวาล่างต้องเป็น "● Server" ไม่มี "รอส่ง" ก่อนปิด
   (เครื่องที่ปิดไปทั้งที่ยังมีงานค้างส่ง จะเอาข้อมูลเลขเก่ามารวมกับข้อมูลใหม่ตอนเปิดครั้งหน้า)
2. สำรองฐาน: `pg_dump -Fc` (เก็บไฟล์ไว้จนกว่าจะตรวจเสร็จ)
3. อัปเดต backend เวอร์ชันนี้ (migration 011 / 012 ทำงานตอนเปิด)
4. ตรวจก่อน (ไม่เขียน): `node scripts/migrate-docids.mjs --json report.json`
   - ดู "เลขชน" ต้องเป็น 0 · "เลขใบชนกับใบที่มีอยู่" ต้องเป็น 0
   - "เลขใหม่ที่มีอยู่แล้วในข้อมูล" ปกติ = ใบเดียวกันที่บางที่แปลงไว้แล้ว (ดูตัวอย่างใน report.json ถ้าจำนวนมาก)
5. แปลงจริง: `node scripts/migrate-docids.mjs --apply --by <ชื่อผู้รัน>` (transaction เดียว · ล็อกตารางระหว่างทำ · ไม่กี่วินาที)
6. เปิดหน้าเว็บ → ตรวจตัวอย่างเอกสาร (RA Reports · ใบโอน · คิว LG02 · ใบชั่ง V4)

**คืนค่า:** `node scripts/migrate-docids.mjs --rollback` (คืนค่าเดิมทุกแถวจาก `docid_migration_backup` · ตัวนับไม่ลด · แผนที่เลขคงไว้ → แปลงซ้ำได้เลขเดิม)
ถ้าคืนค่าไม่ได้: กู้จากไฟล์สำรองข้อ 2

## กันเลขเก่ากลับมา

- server ไม่รับการบันทึกใบที่เลขอยู่ใน `docid_map` (`PUT /docs/...` → 410 พร้อมเลขใหม่)
- `GET /docs/snapshot` ส่งรายการเลขที่เลิกใช้ → bridge ทิ้งใบเลขเก่าในเครื่อง ไม่ส่งขึ้น
- ข้อมูล kv: version ใหม่สูงกว่า → หน้าเว็บที่เปิดใหม่รับค่าจาก server (จึงต้องไม่มีงานค้างส่งตอนแปลง — ข้อ 1)

## ทดสอบ (14 พ.ย.)

- สำเนาฐานในเครื่อง (`whrm_mig`): พบเลขเก่า 38 เลข (ใบชั่ง V4) · เลขชน 0
- ข้อมูลทดสอบทุกตระกูลบนสำเนา: 24/24 — แปลงตรง · SO → SOA · TRF-<ms> เรียงตามเวลาต่อจาก 0007 · Lot/Batch ไม่ถูกแตะ · คีย์เปลี่ยน · version +1 · ใบชั่ง + รายการยังผูกกัน · รันซ้ำไม่ได้ · คืนค่าครบ · แปลงซ้ำได้เลขเดิม
- กันเลขเก่ากลับมา (stack ทดสอบ): 5/5 — server ตอบ 410 · เครื่องที่มีใบเลขเก่าทิ้งใบนั้นและได้ใบเลขใหม่
