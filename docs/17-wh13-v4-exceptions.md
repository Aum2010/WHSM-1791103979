# รายการแก้ไข WH13 / V4 ที่ขอรับรองเป็นข้อยกเว้น "Protected"

ฉบับร่าง 21 พ.ย. 2026 · ตอบเอกสาร "Update 19112026 flow required" ข้อ "WH13 / V4 เป็น Protected — ห้ามแก้ Source / Interface"

## สรุป

- เราไม่ได้แก้ไฟล์ต้นฉบับของทีม UI
  - ไฟล์ WH13.html / V4.html ที่ได้รับ เก็บไว้ตามเดิมทุกไบต์
  - การแก้ทั้งหมดเป็น "hotfix ตอน build" คือแทนข้อความในโค้ดตอนสร้างหน้าเว็บ
  - ทุกข้อมีรหัส มีเหตุผล และถอดออกได้ทีละข้อ
- ถ้าทีม UI ส่งไฟล์ชุดใหม่แล้ว hotfix ข้อที่บังคับ (required) จับโค้ดไม่ได้ ระบบจะ build ไม่ผ่าน จึงไม่มีการแก้เงียบ ๆ
- ปัจจุบันมี hotfix ที่แตะ WH13 / V4 **43 ข้อ** แบ่งเป็น 6 กลุ่ม
- **ขอให้ทีม UI รับรองกลุ่ม 1–3 เป็นข้อยกเว้นถาวร** กลุ่ม 4–5 ถ้าทีม UI แก้ในต้นฉบับเองได้ เราจะถอด hotfix ออก

| กลุ่ม | จำนวน | ถ้าถอดออกจะเกิดอะไร |
|---|---|---|
| 1. ความปลอดภัย (รหัสผ่าน / PIN) | 5 | PIN จริงของพนักงานทั้งโรงงานอยู่ในหน้าเว็บ ใครเปิด View Source ก็เห็น |
| 2. เลขเอกสารจาก server | 10 | สองเครื่องออกเลขเอกสารซ้ำกันได้ |
| 3. จ่ายผ่านขนส่ง: กันยอด + ตัดครั้งเดียว | 7 | สองเครื่องตัดสต็อกใบเดียวกันซ้ำ / จ่ายยอดที่กันไว้ให้ใบอื่นซ้ำ |
| 4. คำสั่งอันตรายเฉพาะผู้ดูแล | 5 | ผู้ใช้ทั่วไปล้างข้อมูลจริง / ใส่ข้อมูลปลอมได้ |
| 5. แก้การแสดงผล / สถานะ | 10 | สถานะ "LG ปฏิเสธ" / "ยกเลิก" แสดงผิด รายงานค้าง PENDING |
| 6. ความลื่น (21 พ.ย.) | 6 | WH13 กิน CPU ตลอดแม้ไม่มีคนใช้ (คอมช้า ~45%) |

## กลุ่ม 3 — จ่ายผ่านขนส่ง (ตัดสินใจ 14 พ.ย. "แบบ ก")

- **ลำดับขั้น:** คลังอนุมัติส่งขนส่ง → กันยอด → LG02 รับงาน → ตัดสต็อก 1 ครั้ง (เครื่องเดียว ตัดสินโดย server)
- **ตัวตัดสต็อก:** ยังเป็นของ WH13 เอง (`[WH-LG-DEFER] v1.3.1`)

| รหัส | ทำอะไร |
|---|---|
| WH13-LG-NO-IMMEDIATE | ปิดโหมด "ตัดทันที" และสวิตช์ปิดในเครื่อง |
| WH13-LG-CUT-ONCE / -BATCH | ก่อนตัด ขอสิทธิ์จาก server · ได้เครื่องเดียว |

| WH13-LG-RESERVE-ON-SEND / -ON-BATCH | กันยอดทันทีที่อนุมัติส่ง |

> **ขอยืนยัน:** เอกสาร 19 พ.ย. เขียนว่า "WH13 ตัด Stock ณ Dispatch Handoff (Contract เดิม)" ซึ่งไม่ตรงกับโค้ด `[WH-LG-DEFER]` ของทีม UI เอง (ตัดตอน LG02 รับงาน) และไม่ตรงกับที่ตกลงวันที่ 14 พ.ย. ขอให้แก้เอกสารเป็น **"กันยอดตอนอนุมัติส่ง · ตัดตอน LG02 รับงาน"**

## กลุ่ม 6 — ความลื่น (ตรวจ 21 พ.ย.)

ผลวัด: WH13 เปิดทิ้งไว้เรียก requestAnimationFrame ~300–600 ครั้ง/วินาที ผ่านตัวดัก rAF ของทีม UI 6 ชั้น (แต่ละชั้นแปลงฟังก์ชันเป็นข้อความ / สร้าง stack trace ทุกครั้ง)

| รหัส | ทำอะไร |
|---|---|
| WH13-RAF-LOOP-ENSURE / -DRIFT / -STAGE | ลูป ensureLoop / driftGuard (2 ตัว) / stageGuard ทำงานจริงทุก 0.8–3 วินาที แต่เรียกทุกเฟรม → setTimeout 250ms |
| WH13-RAF-LOOP-MASTER | masterLoop (ตัวรวมลูป: งานถี่สุดทุก 1.5 วินาที) เรียกทุกเฟรม → setTimeout 250ms |
| WH13-RAF-LOOP-INJECT | injectButtons (ปุ่ม ⑂ ในตารางโอนย้าย) ค้นตารางทุกเฟรม → ทุก 150ms |
| WH13-RAF-SRC-CACHE | ตัวดัก rAF ที่ใช้ String(cb) จำผลต่อฟังก์ชัน (ผลเหมือนเดิม) |

**ขอให้ทีม UI พิจารณาในต้นฉบับ:** ตัวดัก requestAnimationFrame / setInterval / setTimeout ที่ซ้อนกันหลายชั้น (B5.4, FGA_FINALKILL, S3v3 ฯลฯ) เป็น patch แก้ลูปที่ค้าง ถ้าแก้ต้นเหตุของลูปเหล่านั้นแล้วถอดตัวดักออก หน้าจะเบาลงอีกมาก

**นอกเหนือจาก WH13 / V4:**
- **Tailwind:** 13 หน้าโหลด cdn.tailwindcss.com ซึ่งสร้าง CSS ในเบราว์เซอร์ทุกครั้งที่เปิดหน้า (WH13 ~2.3 จาก 5 วินาที) และต้องต่ออินเทอร์เน็ต → เราสร้าง CSS ตอน build แทน (Tailwind 3.4.17 ตัวเดียวกับ CDN · อ่าน tailwind.config ของแต่ละหน้า) ตรวจเทียบภาพหน้าจอกับ CDN แล้วตรงกันทุกหน้า
  - ถ้าโค้ดประกอบชื่อคลาสสีตอนทำงาน (เช่น 'bg-' + สี + '-500/15') ตัว build เผื่อให้อัตโนมัติ แต่**ขอให้เขียนชื่อคลาสเต็ม**ในโค้ดใหม่
- **DBV2-AUTOSYNC-SILENT:** เปิด DBV2.0 ตอนยังไม่มีลูกค้าใน BD02 → เด้งกล่องเตือนทุกครั้ง (โค้ดกำกับว่า "แบบเงียบ" แต่จำลองกดปุ่ม) → ตอนเปิดหน้าเตือนใน console แทน

## นอกเหนือจาก hotfix: ตัวเชื่อม (bridge) ที่ทุกหน้าโหลด

- **Login / สิทธิ์รายส่วน:** ตรวจที่ server (บัญชีกลาง)
- **ข้อมูลในเครื่อง** (`whrm_*` และ key ที่ตกลงกัน): sync ขึ้น server กลาง
  - ใบโอน / คิวขนส่ง เก็บแยกรายใบ
- **21 พ.ย. — ข้อมูลที่ server เป็นเจ้าของ (หน้าเว็บอ่านได้ แต่แก้จากเครื่องไม่ได้):**
  - รายชื่อพนักงาน + หัวหน้าแผนก (`whrm_hrd_employees_v1`) สร้างจากบัญชีกลาง
  - สถานะบัญชี (`whrm_hrd_account_status_v1`) สร้างจากบัญชีกลาง
  - ทะเบียนหน่วยงาน (`hrd_dept_master_v1`) แก้ได้เฉพาะผู้มีสิทธิ์ส่วน HRD

เรื่อง "ไม่ใช้ LocalStorage Wrapper": เราถือเป็นเป้าหมายระยะยาวตามลำดับงานในเอกสาร 19 พ.ย. หน้าที่ต้องมีข้อมูลจริงหน้าใหม่ (PR08 / FA01 / ENG01 / Supplier Portal / CC01 Portal) จะทำเป็น API ของ server ตามแบบเอกสาร ไม่ผ่านตัวเชื่อม
