# WH13 หน่วง (เบิก / คืน / นำส่ง) และการข้าม login ของการอนุมัติจ่าย — 14 พ.ย. 2026

ที่มา: ลูกค้าแจ้งว่าหน้า เบิก / คืน / นำส่ง ของ WH13 หน่วงมาก สลับแท็บไม่ลื่น · ส่งภาพ Performance ของ Chrome DevTools มา

## อาการจากภาพลูกค้า (อัด 15 วินาที บน erp.vnuwin.com)

- Scripting 12.1 จาก 15 วินาที · CPU เต็มเกือบตลอดแม้ไม่ได้กด · INP 4,575 ms · มีเฟรมค้าง 2.3 วินาที
- DOM 31,000–35,000 โหนด · JS heap 29–33 MB (ปกติ) · Network แทบว่าง
- เวลาเกือบทั้งหมดเป็นโค้ดที่ฝังในไฟล์ WH13.html (`[unattributed]` 11.9 วินาที) · bridge ของเรา (`vnuwin.com`) 44 ms

## ทำซ้ำบนเครื่อง

- สลับแท็บ เบิก / คืน / นำส่ง (`switchReqTab`) → หน้าค้าง 1.9–8.5 วินาทีทุกครั้ง
- CPU profile: `document.evaluate` (XPath) 25.8 วินาทีจาก 3 ครั้งที่สลับ · เรียกจาก `injectCheckbox` ใน patch **ULTIMATE_BYPASS_V3** ของลูกค้า
- สาเหตุ: ตัวเฝ้า DOM (`MutationObserver`) เรียก `injectCheckbox()` **ทุก mutation record ที่มีโหนดเพิ่ม** และแต่ละครั้งค้นข้อความ "เลือกโหมดการจ่าย" ด้วย XPath ทั้งหน้า · สลับแท็บครั้งเดียวมีหลายร้อย record · ยังมี `setInterval(injectCheckbox, 1000)` อีกชั้น · DOM ของลูกค้าใหญ่กว่าเครื่องทดสอบ ~4 เท่า จึงหนักกว่า

## ปัญหาความปลอดภัยใน patch เดียวกัน

ULTIMATE_BYPASS_V3 ห่อ `window.__rmaGate`: การอนุมัติที่ชื่อมี `AUTHORIZE` ผ่านทันทีโดยไม่ถามรหัส ในนาม `SYSTEM_BYPASS` (เปิดเป็นค่าเริ่มต้น `isBypassEnabled = true` + ช่องติ๊ก "จ่ายทันที (ไม่ต้องสแกนบาร์โค้ด/Login)")

- `RA_AUTHORIZE` (อนุมัติจ่ายของ) และ `IO_CANCEL_AUTHORIZE` (ยกเลิกใบเบิก) ผ่านโดยไม่ login — ทดสอบยืนยันแล้ว
- มีในไฟล์ตั้งแต่รุ่น 31 ต.ค. (commit `c45a673`) จึงน่าจะอยู่บนระบบจริง
- E2E เดิมไม่จับ เพราะทดสอบหน้าต่าง login ด้วยชื่อรายการอื่น (`E2E_TEST`)

## สิ่งที่แก้ (hotfix ตอน build · ผู้ใช้สั่ง 14 พ.ย.)

| hotfix | แก้ |
|---|---|
| `WH13-NO-LOGIN-BYPASS` (required) | ปิดเงื่อนไขข้าม login → ทุกการอนุมัติต้องยืนยันตัวตน ระบบบันทึกผู้ทำจริง |
| `WH13-NO-BYPASS-CHECKBOX` (required) | ไม่แทรกช่องติ๊ก "จ่ายทันที" · ตัดการค้น XPath ทั้งหน้าออก (ต้นเหตุความหน่วง) |
| `WH13-BYPASS-OBS-THROTTLE` | กันไว้ถ้าลูกค้าแก้ `injectCheckbox`: รวมการเรียกเป็นครั้งเดียวทุก 0.3 วินาที |

ตรวจแล้วว่าการแทน `__rmaGate` อีก 2 จุดใน WH13 ไม่ใช่การข้าม login: บรรทัดรับของ (`doReceive`) ส่งผู้ใช้ที่ตรวจรหัสด้วย `checkUser` แล้ว · `__fgtB2Unlock` เป็นคำสั่ง console ปลดล็อกรายการคลังปลายทาง FGT

## ผลทดสอบ (stack ทดสอบ · ฐาน whrm_r5)

- ค้างหลังสลับแท็บ (ภายใน 3 วินาที): ก่อนแก้ 1.9–8.5 วินาที → หลังแก้ 0–0.2 วินาที
- อนุมัติจ่าย / ยกเลิกใบเบิก: ไม่ผ่านอัตโนมัติ · รหัสผิดไม่ผ่าน · รหัสถูกผ่านในนามผู้ที่ login จริง · ไม่มีช่องจ่ายทันที (5/5)
- E2E: เพิ่มข้อ "อนุมัติจ่าย / ยกเลิกใบเบิก ต้อง login" · ผลรอบเต็ม ดูหัวข้อถัดไป

### E2E รอบเต็ม

- cross-origin **162/162** (รวมข้อใหม่) · proxy 157/161 — 4 ข้อที่ตกคือ V4 นำส่ง WMS บนฐานข้อมูลใหม่เอี่ยมรอบแรก อาการเดิมที่บันทึกไว้ตั้งแต่ 31 ต.ค. ไม่เกี่ยวกับการแก้นี้
- ขึ้น Docker บนเครื่อง (:8080) แล้ว
