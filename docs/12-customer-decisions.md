## ผลต่องานเดิม

- **ข้อ 4:** LG02 โพสต์ Stock OUT ตอนยืนยันรถออก และ Stock IN ตอนรับปลายทาง ต้องย้าย OUT ไปรวมกับการรับ และคงการกันยอดไว้ระหว่างขนส่ง ไม่อย่างนั้นของบนรถจะถูกจ่ายซ้ำได้ · คู่มือ L3–L4 และ `01-sequence-diagrams.md` ข้อ 8 ต้องแก้หลังแก้โค้ด
- **ข้อ 8:** ของที่อยู่ในคลังวันเริ่มระบบต้องผ่านการรับเข้าทั้งหมดก่อน จึงจะจ่ายออกได้
- **ข้อ 9:** ขัดกับแผนเดิมที่ให้ server ปฏิเสธรายการเมื่อยอดไม่พอ ต้องรับรายการจากเครื่องที่ offline ไว้ก่อน แล้วนำรายการที่ชนกันเข้าคิวให้คนตรวจ
- **ข้อ 10 กับ 11–14:** ลูกค้าจะพัฒนา BD02 ในเดือน พ.ย. จึงอาจชนกับ hotfix และตัวเชื่อมตารางขายของ BD02

### HRD01 แบบย่อ — ทำแล้ว (14 พ.ย.)

- หน้า HRD01 = ทะเบียนพนักงาน + สิทธิ์รายส่วน อ่าน / เขียนข้อมูลชุดเดียวกับหน้าจัดการผู้ใช้ (`GET/POST/PUT /api/v1/hr/users`) · บันทึกแล้วมีผลทันที
- ต้นแบบของลูกค้าถูกซ่อน (hotfix `HRD01-LITE`) เพราะเก็บในเครื่อง และบังคับกรอกข้อมูลส่วนตัว (เลขบัตรประชาชน / วันเกิด / ที่อยู่ / บัญชีธนาคาร) ที่ server ยังไม่มีที่เก็บ
- ช่องที่มี: ชื่อผู้ใช้ · ชื่อ-สกุล · แผนก · ตำแหน่ง · รหัสบัตร · สถานะ (ใช้งาน / ระงับ) · รหัสผ่าน (พนักงานต้องเปลี่ยนเองตอน login ครั้งแรก) · ระดับ HRD01 · ส่วนที่ใช้ได้
- ระดับต่อคน → สิทธิ์ของส่วนที่ติ๊ก: 1–3 = ใช้งาน · 4 = อนุมัติ · 99 = ผู้ดูแล (ผู้ดูแลระบบเท่านั้น) · ส่งเฉพาะส่วนที่เปลี่ยน → สิทธิ์ที่ผู้ดูแลตั้งละเอียดไว้ไม่ถูกทับ
- "ดูอย่างเดียว" ยังตั้งที่หน้าจัดการผู้ใช้ (ผู้ดูแล) · ใน HRD01 แสดงเป็นล็อก
- เปิดหน้าได้: ผู้ดูแล หรือผู้มีสิทธิ์ส่วน **HRD** ระดับใช้งานขึ้นไป (template ใหม่ "ฝ่ายบุคคล (HR)")
- server กัน HR: ไม่เห็น / แก้บัญชีผู้ดูแล (บทบาท ADMIN · ส่วนใดระดับผู้ดูแล · ระดับ 99) · ตั้งบทบาท / template / ระดับ 99 / สิทธิ์ผู้ดูแลไม่ได้ · แก้สิทธิ์ / ระดับ / สถานะของตัวเองไม่ได้ · รีเซ็ตรหัสแล้วเจ้าของต้องตั้งใหม่
- ยังไม่ทำ (ขั้นถัดไป): ขอสิทธิ์ → อนุมัติโดยคนละคน · วันเริ่ม / หมดอายุสิทธิ์ · WH13 ใช้ระดับจาก server แทน Authorized list · ข้อมูลงาน HR (กะ / เวลา / OT / ความสามารถ) · ข้อมูลส่วนตัว
