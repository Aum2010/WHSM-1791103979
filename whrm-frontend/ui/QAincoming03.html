🛡️ กฎการตรวจรับ / รับคืน (Rule Master)

แหล่งกฎกลางของ WH13 — แก้ไขได้ที่นี่ที่เดียว · WH13 อ่านกฎไปตรวจทุกครั้งที่เลือกประเภท QA Issue / General Receive

กำลังโหลด…
ℹ️
WH13 ใส่ ประเภทการตรวจรับ ของทุกรายการรับเข้าให้อัตโนมัติตามกฎนี้ และล็อกไว้ — รับเข้าไม่สามารถ Override ที่ WH13 ได้ (ต้องเปลี่ยนกฎที่นี่) · สินค้าที่ไม่มีกฎ = ผู้ใช้เลือกเอง · กฎที่ตั้งขอบเขต “รับคืน / ทั้งสอง” จะใช้กับ RU ด้วย (รับคืน Override ได้ ดูแท็บ B)
ข้อยกเว้น PRP (ชั่งเตรียม → WHSM07) — ผ่านการตรวจของ QA มาแล้วตั้งแต่ขั้นรับเข้า/รับคืน จึงเป็น General Receive ทันทีที่ใช้โหมด PRP และ ไม่อยู่ในเงื่อนไขของกฎทั้งหมดในแท็บนี้
รหัสสินค้า ชื่อสินค้า (DBV2.0) บังคับใช้ ใช้กับ เหตุผล (แสดงที่ WH13) ใช้งาน ลบ

ตรวจก่อนประกาศใช้: เหตุผลต้องไม่ว่าง · รหัสที่ไม่พบใน DBV2.0 (เตือน) · กฎใหม่มีผลกับ RO ที่สร้างหลังประกาศใช้ และ RU ที่เริ่มตรวจรับหลังประกาศใช้ — เอกสารเก็บ “กฎ ณ ตอนนั้น” ไว้ ไม่ถูกเปลี่ยนย้อนหลัง

ℹ️
สาเหตุการคืนที่ตั้งไว้ที่นี่จะเป็น ตัวเลือกในฟอร์มคืนของ WH13 โดยอัตโนมัติ — เพิ่ม / ลบ / ปิดใช้งานได้ · กำหนดว่าสาเหตุใดต้องผ่าน QA Issue หรือ General Receive · “เลือกเอง” = ไม่ล็อก WH เลือกประเภทเอง
สาเหตุการคืน บังคับใช้ ข้อความที่แสดงที่ WH13 ใช้งาน ลบ

ลำดับการตัดสินตอนตรวจรับคืน (RU)

  1. กฎตามรหัสสินค้า (ขอบเขต “รับคืน” หรือ “ทั้งสอง”) — ถ้ามีรหัสใดใน RU บังคับ QA → QA Issue
  2. กฎตามสาเหตุการคืน (ตารางด้านบน)
  3. ไม่มีกฎ / เลือกเอง — WH เลือกเอง ระบบแนะนำจากแผนกเป็นข้อมูลประกอบ ไม่ล็อก
ถ้ากฎขัดกัน QA Issue ชนะเสมอ

ตัวอย่าง

RU มีสินค้า 3A002 (กฎ: QA) และสาเหตุ “เบิกเกินความต้องการ” (กฎ: General Receive)
ผล: บังคับ QA Issue · ที่มา: รหัส 3A002
ถ้า WH ต้องการใช้ General Receive จริง ขอ Override ที่ WH13 ได้ (เฉพาะผู้มีสิทธิ์) — ใช้เฉพาะ RU ใบนั้น ไม่แก้กฎ
